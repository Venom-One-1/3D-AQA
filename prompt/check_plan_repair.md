# 检查计划离线修复

原始回答与首次通过率保留不变。此程序读取已有回答，在独立目录修复格式与契约问题，然后重新执行冻结关节缓存，不调用 API。

```bash
conda activate 4d-humans
cd /home/sqw/Projects/3D-AQA
python run_check_plan_repair.py
```

默认来源：`check_plan_experiment/first3_v1/`。
默认输出：`check_plan_experiment/first3_v1_repaired_v1/`。
输出目录必须不存在；重新运行请指定新的 `--output-root`，不会覆盖已有结果或人工复核记录。
`--skip-execution` 仅修复并校验，不执行关节缓存。

## 修复原则

- 使用 JSON 解析器定位唯一完整对象，不按首尾括号截取，也不自动选择多个候选中的一个。
- 原文中未转义引号存在歧义，使用经助手核对、与原文 SHA256 绑定的精确字符串清单；不做全局正则替换。
- 合并完全相同的测量定义，同步引用；同一要领的重复证据合并分量、保留双方解释。不同尺度、坐标或关节顺序不自动合并。
- 删除没有被任何要领引用的查询，但不删除动作要领，不自动补写缺失的检查。
- 引用拼写错误仅在关节、坐标、尺度和文本意图明确对应时由助手锁定修复清单，程序不模糊猜测 ID。
- 方向修正同时处理分量与符号。例如 left>0 等价于 right<0；身体左右不等于图像左右。
- 修复清单不能改动关节、坐标系、归一化方式、动作要领或支持分类；只允许精确修正证据引用、分量及其说明。
- 仍使用原严格验证器，不靠放松标准提高通过率。语义准确率仍为未知。

`prompt/check_plan_repair_policy_v1.json` 保存助手逐项核对过的转义、引用和方向修正；这不是模型自主修复结果，也不是专家标注。
它绑定当前原始回答的哈希，不能无条件应用到另一批回答。

## 输出

| 文件 | 内容 |
|---|---|
| `repair_report.md` | 修复前后通过情况、执行情况、查看入口 |
| `plan_report.md` | 修复后每条要领与查询、预期关系、局限的对照 |
| `repair_actions.csv` | 每项修改的原因、位置、修改前后内容 |
| `validation.csv` | 各回答首次与修复后校验、查询数量和执行状态 |
| `plan_review.csv` | 仅用于进一步语义复核，初始全部 pending |
| `Mxx_Rxx/original_answer.txt` | 原始回答的逐字节副本 |
| `Mxx_Rxx/plan.json` | 修复后的计划 |
| `Mxx_Rxx/repair_log.json` | 来源哈希、校验结果、修改记录、剩余语义警告 |
| `Mxx_Rxx/measurements/` | 同一计划在十名教师及五名学生上执行的几何证据 |
| `geometry_probes.json` | 生成查询的几何行为核验，不是动作错误标签 |
| `repair_manifest.json` | 原实验全文件哈希、修复策略与代码哈希、缓存哈希和不变性检查 |

按重复顺序选择每式首个可执行修复版，不按学生结果挑选。保留首次通过率与修复后通过率，不用后者替代模型原始表现。
本轮不生成学生训练反馈，不把计划中模型自行给出的数值范围当成已验证的质量阈值。
